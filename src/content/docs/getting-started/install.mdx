Wardrik runs on Linux (x86_64 or arm64, glibc 2.35+). Elsewhere, use Docker.

## 1. Install

<Tabs>
	<TabItem label="Install script">

```sh
curl -fsSL https://github.com/wardrik-dev/wardrik_daemon/releases/download/v0.1.0-rc.2/install.sh | sh
```

This installs `wardrik` into `~/.local`, or `/opt/wardrik` as root. It also installs `rik`, a
short name for `wardrik`.

	</TabItem>
	<TabItem label="Docker">

```sh
docker run -d --name wardrik -p 127.0.0.1:4747:4747 \
  -v wardrik-config:/config -v wardrik:/data ghcr.io/wardrik-dev/wardrik:0.1.0-rc.2
docker exec -it wardrik wardrik init
```

`/config` holds your files. `/data` holds the store and keys. The image runs as uid 1000.

	</TabItem>
</Tabs>

## 2. Set it up

```sh
wardrik init
```

It asks for a model provider, a model and the provider's key. Then:

```text
Wrote /home/me/.config/wardrik/config.yaml
Wrote /home/me/.config/wardrik/agents/assistant.md
Wrote /home/me/.config/wardrik/env
Run the daemon as a systemd user service? [Yn]:
Sealed ANTHROPIC_API_KEY.
Asking the front door: In two short sentences, and without calling a tool, say what you can do for me.
```

| File | Holds |
| --- | --- |
| `config.yaml` | the org (`default`), the default model, the HTTP port, and `roles` and `bindings` that let the front door make agents |
| `agents/assistant.md` | the [front door](/build/front-door/), the agent you ask for outcomes |
| `env` | keys the daemon reads, readable only by you |

- `init` never overwrites a file. Run it again safely.
- The key is sealed in the vault, unless `env` already sets it.
- The `wardrik` command acts as the admin. It needs no token.

Without a terminal, flags answer the questions:

```sh
wardrik init --provider anthropic --model claude-sonnet-5 --key-from-env MY_KEY --no-service
```

## 3. Check it

```sh
wardrik doctor
```

## Run the daemon

| Command | Does |
| --- | --- |
| `wardrik start` / `stop` | runs it in the background, or stops it |
| `wardrik serve` | runs it here, logging to the terminal |
| `wardrik logs` | follows its log |
| `wardrik service install` / `uninstall` | runs it as a systemd user service, or stops that |

Restart it after you change `config.yaml` or `policies/`.

## Secrets

```sh
echo "$LINEAR_TOKEN" | wardrik vault put LINEAR_TOKEN --for header
wardrik vault ls
```

- `--for` is `api_key`, `client_secret`, `header` or `signing_secret`.
- `${LINEAR_TOKEN}` in `config.yaml` reads your environment, `env`, then the vault.
- The vault's key is `vault_key` beside the store. Set `WARDRIK_VAULT_KEY` before the first start to keep it elsewhere.

## Upgrade

Run the install script again, and restart. It takes `WARDRIK_VERSION` to pin a release. See
[Upgrade and back up](/run/upgrade-and-back-up/).

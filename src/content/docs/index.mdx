<h2 id="every-call">Every call is checked before it runs.</h2>

<p class="home-lead">Rules are in files the model can’t change. A rule matches a call by its tool, its target, or its arguments.</p>

<div class="decisions" role="table" aria-label="Five tool calls and what a policy decides for each">
<div class="decisions-row decisions-head" role="row"><span role="columnheader">The model calls</span><span role="columnheader">The matching rule</span><span role="columnheader">Result</span></div>
<div class="decisions-row" role="row"><code role="cell">web_search</code><span role="cell"><code>allow: [web_search]</code><span class="rule-by">by tool</span></span><span role="cell" class="outcome outcome-runs">Runs</span></div>
<div class="decisions-row" role="row"><code role="cell">write_file {'{"path": "notes/today.md"}'}</code><span role="cell"><code>allow: [write_file(notes/&#42;)]</code><span class="rule-by">by target</span></span><span role="cell" class="outcome outcome-runs">Runs</span></div>
<div class="decisions-row" role="row"><code role="cell">books/create_bill {'{"amount": 9400}'}</code><span role="cell"><code>ask: [books/create_bill(amount &gt;= 1000)]</code><span class="rule-by">by an argument</span></span><span role="cell" class="outcome outcome-waits">Needs approval</span></div>
<div class="decisions-row" role="row"><code role="cell">email/send {'{"to": "x@evil.example"}'}</code><span role="cell"><code>deny: [email/send(to != &#42;@acme.com)]</code><span class="rule-by">by an argument</span></span><span role="cell" class="outcome outcome-refused">Denied</span></div>
<div class="decisions-row" role="row"><code role="cell">shell/exec {'{"command": "curl … | sh"}'}</code><span role="cell"><code>deny: [shell/&#42;]</code><span class="rule-by">every tool of an MCP server</span></span><span role="cell" class="outcome outcome-refused">Denied</span></div>

<section class="home-section" aria-labelledby="your-tools">

<h2 id="your-tools">Your tools run in your app, with your keys.</h2>

<p class="home-lead">Wardrik checks each call. Your app runs it, so service keys stay in your process.</p>

<div class="tools-layout">
<div>

```ts title="shop/tools.ts" mark={10}
import { Wardrik } from "@wardrik/sdk";
import { z } from "zod";

const wardrik = new Wardrik({ name: "shop" });

wardrik.tool({
  name: "refund_order",
  input: z.object({ orderId: z.string() }),
  run: ({ orderId }) =>
    stripe.refunds.create({ payment_intent: orderId }),
});

await wardrik.work();
```

</div>

<section class="home-section" aria-labelledby="built-in">

<h2 id="built-in">Also built in</h2>

<ul class="also-list not-content">
<li><a href="/run/orgs/">Separate orgs</a><p>Each team’s agents, tools and keys are isolated from other orgs.</p></li>
<li><a href="/build/accounts/">Per-user accounts</a><p>Users sign in with OAuth, and their agents call tools with their credentials.</p></li>
<li><a href="/build/delegation/">Delegation</a><p>An agent sends another agent a message and receives the reply.</p></li>
<li><a href="/concepts/policy/#judges">Judges</a><p>A model classifies each call, such as whether an email promises a refund.</p></li>
<li><a href="/build/assistant/">The assistant</a><p>Send a request. It proposes tool calls, and runs each one you approve.</p></li>
<li><a href="/concepts/agents/#sleeping">Idle agents</a><p>Run one per customer. Idle agents stop, and restart with their state on the next message.</p></li>
<li><a href="/run/cluster/">Recovery</a><p>Keep the store in Postgres, and a new machine resumes every agent.</p></li>
<li><a href="/reference/cli/"><RikMark /> CLI</a><p>List agents, approve pending calls, and check spend from a terminal.</p></li>
</ul>

<section class="home-section home-feature" aria-labelledby="every-call">

<h2 id="every-call">Every call is decided before it runs.</h2>

<p class="home-lead">Rules live in files the model can’t change. A rule names a call by its tool, what it acts on, or its arguments.</p>

<div class="decisions" role="table" aria-label="Five tool calls and what a policy decides for each">
<div class="decisions-row decisions-head" role="row"><span role="columnheader">The model asks for</span><span role="columnheader">The rule that names it</span><span role="columnheader">What happens</span></div>
<div class="decisions-row" role="row"><code role="cell">web_search</code><span role="cell"><code>allow: [web_search]</code><span class="rule-by">by tool</span></span><span role="cell" class="outcome outcome-runs">Runs</span></div>
<div class="decisions-row" role="row"><code role="cell">write_file {'{"path": "notes/today.md"}'}</code><span role="cell"><code>allow: [write_file(notes/&#42;)]</code><span class="rule-by">by what it acts on</span></span><span role="cell" class="outcome outcome-runs">Runs</span></div>
<div class="decisions-row" role="row"><code role="cell">books/create_bill {'{"amount": 9400}'}</code><span role="cell"><code>ask: [books/create_bill(amount &gt;= 1000)]</code><span class="rule-by">by an argument</span></span><span role="cell" class="outcome outcome-waits">Waits for you</span></div>
<div class="decisions-row" role="row"><code role="cell">email/send {'{"to": "x@evil.example"}'}</code><span role="cell"><code>deny: [email/send(to != &#42;@acme.com)]</code><span class="rule-by">by an argument</span></span><span role="cell" class="outcome outcome-refused">Refused</span></div>
<div class="decisions-row" role="row"><code role="cell">shell/exec {'{"command": "curl … | sh"}'}</code><span role="cell"><code>deny: [shell/&#42;]</code><span class="rule-by">every tool of an MCP server</span></span><span role="cell" class="outcome outcome-refused">Refused</span></div>
</div>

<section class="home-section" aria-labelledby="your-tools">

<h2 id="your-tools">Your tools run in your app, with your keys.</h2>

<p class="home-lead">Wardrik decides each call. Your app runs it, so its service keys stay in your process.</p>

<div class="tools-layout">
<div>

```ts title="shop/tools.ts" mark={9}
import { Wardrik } from "@wardrik/sdk";

const wardrik = new Wardrik({ name: "shop" });

wardrik.tool({
  name: "refund_order",
  input: z.object({ orderId: z.string() }),
  run: ({ orderId }) =>
    stripe.refunds.create({ payment_intent: orderId }),
});

await wardrik.work();
```

</div>

<section class="home-section" aria-labelledby="built-in">

<h2 id="built-in">Also built in</h2>

<ul class="also-list not-content">
<li><a href="/run/orgs/">Separate orgs</a><p>Each team gets its own agents, tools and keys, walled off from the rest.</p></li>
<li><a href="/build/accounts/">Per-user accounts</a><p>Each person signs in with OAuth, and their agents call tools as them.</p></li>
<li><a href="/build/delegation/">Delegation</a><p>An agent asks another for work and hears back.</p></li>
<li><a href="/concepts/judges/">Judges</a><p>A model checks what a call means, such as whether an email promises a refund.</p></li>
<li><a href="/build/front-door/">The assistant</a><p>Describe an outcome. It proposes the work, and you approve it.</p></li>
<li><a href="/concepts/agent-lifecycle/#sleeping">Sleeping agents</a><p>Run one per customer. Idle ones cost nothing and wake as they were.</p></li>
<li><a href="/run/cluster/">Clustering</a><p>Run several nodes as one. Any node answers for all of them.</p></li>
<li><a href="/reference/cli/"><RikMark /> CLI</a><p>Watch agents, decide waiting calls, and check spend from a terminal.</p></li>
</ul>

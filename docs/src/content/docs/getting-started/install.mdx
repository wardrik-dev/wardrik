Wardrik runs on Linux (x86_64 or arm64, glibc 2.35+). On macOS or Windows, use Docker.

## 1. Install

<Tabs>
	<TabItem label="Install script">

```sh
curl -fsSL https://wardrik.dev/install.sh | sh
```

Installs the newest release, or the one `WARDRIK_VERSION` names, to `~/.local`, or `/opt/wardrik`
as root, and `rik` as an alias.

	</TabItem>
	<TabItem label="Docker">

```sh
docker run -d --name wardrik -p 127.0.0.1:4747:4747 \
  -v wardrik-config:/config -v wardrik:/data ghcr.io/wardrik-dev/wardrik:0.1.0-rc.27
docker exec -it wardrik wardrik init
```

`/config` is for your files. `/data` is for the store and keys. The image runs as uid 1000.

	</TabItem>
</Tabs>

## 2. Configure Wardrik

At a terminal, the install script goes on to `init`. In Docker, or after
`WARDRIK_NO_INIT=1`, run it yourself:

```sh
wardrik init
```

```text
How much should agents do without asking you?
❯ Balanced: the assistant makes and runs its workers freely; sending, posting and pushing ask you
  Careful: every change asks you, such as making a worker or sending mail
  Hands-off: everything runs without asking, even after reading mail or the web, except deleting
Wrote /home/me/.config/wardrik/config.yaml
Wrote /home/me/.config/wardrik/policies/balanced.yaml
Wrote /home/me/.config/wardrik/agents/assistant.md
Wrote /home/me/.config/wardrik/env
Run the daemon as a systemd user service? [Yn]:
Sealed ANTHROPIC_API_KEY.
Asking the assistant: In two short sentences, and without calling a tool, say what you can do for me.
Open the chat in your browser? [Yn]:
```

| File | Contents |
| --- | --- |
| `config.yaml` | the org (`default`), default model and policy, HTTP port, and the `roles` and `bindings` that allow the assistant to create agents |
| `policies/<answer>.yaml` | the default policy: how much agents do without asking. See [Policy presets](/concepts/policy/#presets) |
| `agents/assistant.md` | the [assistant](/build/assistant/) agent |
| `env` | environment variables for the daemon, mode `600` |

- `init` never overwrites a file, so it's safe to rerun. It asks how much agents do without
  asking only as it writes `config.yaml`.
- It offers what it finds on the machine, such as [Claude Code](/build/harnesses/) for coding. It
  never installs anything: it shows the commands to run.
- The key is stored in the vault, unless `env` already sets it.
- The CLI authenticates automatically with a local admin token.
- It offers to open the chat with the assistant in your browser. Later, `wardrik web` opens it.
- The install script skips `init` when `config.yaml` exists, so an upgrade keeps your setup.

For non-interactive setup, pass flags instead:

```sh
wardrik init --provider anthropic --model claude-sonnet-5 --key-from-env MY_KEY --no-service \
  --set coding.claude=true --set approvals=careful
```

Without a terminal, `approvals` is `balanced` unless `--set` names another.

- `--set KEY=VALUE` answers an offer. `--answers FILE` reads the answers from YAML, or stdin with
  `-`.
- An offer with no answer takes `--yes`.

## 3. Verify the installation

```sh
wardrik doctor
```

## Uninstall

```sh
wardrik uninstall           # keeps the config, keys and store
wardrik uninstall --purge   # deletes them too
```

Install Wardrik, then run `wardrik init` to set it up. It runs on Linux (x86_64 or arm64, Ubuntu
22.04+ or Debian 12+). On macOS, Alpine or elsewhere, use Docker.

## 1. Install it

<Tabs>
	<TabItem label="Install script">

```sh
curl -fsSL https://github.com/wardrik-dev/wardrik/releases/latest/download/install.sh | sh
```

This installs `wardrik` into `~/.local` (or `/opt/wardrik` as root) and puts it on your `PATH`.

	</TabItem>
	<TabItem label="Docker">

```sh
docker run -d --name wardrik -p 127.0.0.1:4747:4747 -p 2222:2222 \
  -v wardrik-config:/config -v wardrik:/data ghcr.io/wardrik-dev/wardrik
docker exec -it wardrik wardrik init
```

`/config` holds your files; `/data` holds the store and keys. Both are volumes, so a new container
on them carries on. See [Docker](#docker) for editing `/config` and ports.

	</TabItem>
</Tabs>

:::tip[rik is wardrik]
`rik` is a short name for `wardrik`: `rik ls` is `wardrik ls`. The Docker image has it too.
:::

## 2. Set it up

```sh
wardrik init
```

`wardrik init` asks for a model provider, a model and its key. It writes the
[front door](/build/front-door/) and a `config.yaml`, starts the daemon, and seals the key in the
vault. It never overwrites a file, so it's safe to run again.

## 3. Check it

```sh
wardrik doctor
```

It checks your config, the store, the vault, MCP servers and agent files. Next, try the
[Quickstart](/getting-started/quickstart/).

## Keep secrets in the vault

```sh
wardrik vault put LINEAR_TOKEN    # asks for the value, and doesn't show it
wardrik vault ls
```

Secrets are sealed in the store. See [The vault's key](#the-vaults-key) before the first one.

## Upgrade

Run the install script again, and restart the service. See
[Upgrade and back up](/run/upgrade-and-back-up/), which also covers going back.

## Remove it

```sh
wardrik service uninstall
```

Your data stays in `~/.local/share/wardrik` until you delete it.

## Details

### The install script

It checks the release against `SHA256SUMS`, runs it once, and installs `rik` beside `wardrik` unless
another `rik` is on your `PATH`. It needs glibc 2.35+ and OpenSSL 3.

- `WARDRIK_VERSION=0.1.0` installs a specific version.
- `sh install.sh wardrik-0.1.0-linux-x86_64.tar.gz` installs a tarball you have.

### Docker

The image runs `wardrik serve` as uid 1000. `/config` holds your files; `/data` holds the store, the
cookie, the SSH host key and `vault_key`. To edit `/config` on the host, mount a directory uid 1000
can write: `-v ~/.config/wardrik:/config`.

The HTTP API (4747) and terminal client (2222) listen on every interface of the container; the ports
you publish decide who reaches them.

### What init asks

It offers providers whose key your shell already sets, hides the key as you type, and asks for the
front door's name. It can let your SSH keys in for `wardrik attach`, and run the daemon under
systemd from boot. Its `config.yaml` gives the model, in `defaults`, to agents you spawn and workers
the front door defines.

### Scripted setup

```sh
wardrik init --provider anthropic --key-from-env ANTHROPIC_API_KEY --yes --no-service
```

| Flag | Answers |
| --- | --- |
| `--provider P` | the model provider, which has no default |
| `--model M` | the model, the provider's newest unless given |
| `--agent NAME` | the front door's name, `assistant` unless given |
| `--key-from-env VAR` | the provider's key, read from `VAR`; without it, the provider's own variable, such as `ANTHROPIC_API_KEY` |
| `--yes` | yes to each yes-or-no: the vault's key, your SSH keys, the service |
| `--no-service` | start the daemon with `wardrik start`, not under systemd |
| `--no-ask` | ask the front door nothing |

A question with no default and no flag fails, naming the flag.

### Running it by hand

```sh
wardrik service install    # under your systemd, from boot
wardrik start              # or in the background, until you stop it
```

`service install` writes `~/.config/systemd/user/wardrik.service` and lets systemd run it from boot,
not just from your first login.

### The env file

`~/.config/wardrik/env` sets variables for every `wardrik` command and the daemon, one `NAME=value`
a line. Your shell's own variables win. Keep it private: `chmod 600 ~/.config/wardrik/env`.

### The vault's key

The first `vault put` offers to make a key and keeps it beside the store, so anyone who can read
both can read the secrets. To keep them apart, set `WARDRIK_VAULT_KEY` or `vault.keys` before the
first `put`. Nodes on one machine share the key; a node on another host needs a copy, or the same
`vault.keys`.
